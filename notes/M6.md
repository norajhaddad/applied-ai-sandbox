# M6

## Copilot

- Copilot autocompleted my function the instant I paused, but because it pattern-matches the surrounding code instead of reading my CLAUDE.md or project conventions the way Claude Code does, it is great for boilerplate yet can't be trusted to follow our project rules.

## Cursor

- I'd reach for Cursor when I want to make and visually review a quick multi-file change inside the editor — its inline Composer diffs and @-file context make in-IDE edits fast and easy to eyeball — but I'd stay in Claude Code for longer, autonomous, convention-heavy or terminal-and-git work where reading CLAUDE.md and running the whole task end to end matters more than seeing each diff.

## Gemini CLI

- Both tools answered correctly, but Claude Code's summary felt more precise and grounded in the repo's conventions because it leaned on CLAUDE.md, while Gemini CLI was faster and navigated the codebase more aggressively up front — so I'd pick Gemini for quick broad exploration and Claude Code when accuracy and following project rules matter.

## Chat

- When I pasted the Task 1 diff (adding "tags": [] in new_note) into chat and asked for a code review, it flagged that the default is only set at this one creation point, so any note made by another code path or already sitting in app.notes won't have a tags key and later code reading note["tags"] could KeyError — it suggested reading with note.get("tags", []) or centralizing note creation in a make_note() helper, exactly the missing-default-everywhere risk I'd want a junior reviewer to catch.

## Tool decision matrix

| Situation | Tool I'd reach for | Why |
|---|---|---|
| Repetitive boilerplate inside a file (obvious next line, simple dict/getter) | GitHub Copilot | Instant grey-text completion that pattern-matches nearby code; no prompt needed. |
| A multi-step feature that must follow our conventions (CLAUDE.md, tests-as-spec, branch/PR flow) | Claude Code | Reads CLAUDE.md automatically and runs tests + git end to end, autonomously across files. |
| A quick multi-file edit I want to approve as inline diffs while reading code | Cursor | Composer shows the diff inline and @-references pull in context — fast to eyeball and accept. |
| Getting oriented fast in an unfamiliar codebase | Gemini CLI | Large context window navigates aggressively and reads many files quickly for broad orientation. |
| Thinking through tradeoffs before any code, or learning a concept | Chat (Claude.ai / ChatGPT) | No file access is the point — it stays conversational and code-free, ideal for planning/concepts. |
| Reviewing a diff/PR or writing prose (commit message, PR description) | Chat (Claude.ai / ChatGPT) | Paste the diff, ask "what risks do you see?" — strong at review and writing without touching the repo. |
